# PresenceKit Admin 第一阶段视觉规范

当前选定方向见 [REFINED_DESIGN.md](REFINED_DESIGN.md)，预览 `refined.html`。以下保留初版 A/B/C 的设计记录。

## 范围与预览

这是独立设计参考，不是已接入的管理面。全部文件位于 `ui-prototypes/admin-phase1/`，没有导入生产 CSS/JS，没有 fetch、接口调用、持久化或权限改动。

直接用 Chrome 或 Edge 打开 `index.html`，再选择方向；也可直接双击 `a-dark.html`、`b-mist.html`、`c-professional.html`。保持本目录中的 `styles.css` 和 `app.js` 与 HTML 同目录。无构建步骤、无依赖安装、无需启动真实服务。

本次对照的是仓库现有吃食模块，当前消息未附截图。示例记录是虚构的功能演示数据，不读取真实用户记录。

## 只读检查结论

- `admin/static/index.html` 是原生 HTML 入口，加载 `style.css` 和后置 `admin-design.css`；后者覆盖卡片、按钮、折叠、操作区等公共规则。
- `admin/static/js/core.js` 按需加载 `pages/` HTML 片段，并带片段版本参数；公共组件以 CSS 类和原生元素复用，没有发现此入口依赖组件框架。
- `admin/static/pages/tools.html` 的示范模块包含自动记录开关、角色 ID、食品或店名查询、失败重试、食品名称、本人评价原话、喜恶选择和提交更正。
- `admin/static/js/tools.js` 连接这些操作；现有查询区直接展示序列化结果。样机把同类信息呈现为食品、当前评价、本人原话、来源和时间，未改 API 或字段合同。
- 保留模块所属“角色能使用哪些工具”的上下文，不提议导航分类迁移。页顶 A/B/C 是样机比较入口，不是生产导航。

## 组件与行为

| 组件 | 规范 |
| --- | --- |
| 页面标题 | 面包屑、功能名、简介、样机状态；标题不混入内部函数或路由字段 |
| 概况 | 记录数、待处理数、失败数；颜色只补充语义，不代替文字 |
| 一级卡片 | 原生 details / summary，标题、说明、关键状态与展开指示一直可见；没有嵌套折叠 |
| 表单 | label 包含对应控件；字段间距 16px，C 12px；输入最大 360px，长文本最大 640px |
| 主操作 | 实色按钮：保存、查询、提交更正 |
| 次操作 | 边框按钮：重试、填入演示评价 |
| 危险操作 | 红色边框和文字，只用于重置样机；原生确认后才清空本页输入 |
| 反馈 | 成功、错误、空状态均有完整文字；动态反馈使用 role=status / aria-live |
| 查询结果 | 桌面列式行，窄窗口堆叠为记录卡；长内容自动换行 |
| 开关 | 原生 checkbox，role=switch；区分未保存状态和已保存状态 |

展开/收起不卸载 DOM，不清空输入，不自动提交。正在编辑的模块默认展开。刷新或明确重置才恢复初始示例。三个方向使用同一份脚本与数据，反馈、字段、操作一致。

该模块真实业务开关只有自动记录，因此没有添加虚构设置。长表单用真实查询、更正字段及说明展示：A 两列纵向配置，B 宽屏分区并列，C 三列紧凑配置。后续其他长设置页可复用 fields 网格，不需要把每个字段无限拉宽。

## 响应式与可访问性

- 宽屏：A 最大 1280px 主区+300px 说明栏；B 最大 1440px、查询全宽、配置并列；C 最大 1480px 主区+260px 说明栏。
- 1000px 以下：侧栏落到内容下方；B 并列配置转为单列。
- 600px 以下：表单与结果转单列，按钮换行，标题/状态可换行；页面左右保留 16px。
- 不使用固定宽度表格或 overflow-x:hidden 掩盖溢出。网格 minmax(0,1fr)、控件 min-width:0 和结果换行负责收缩。
- Tab 可定位输入、按钮、summary；Enter/Space 可切换原生折叠；表单支持 Enter 提交。焦点有 2px 轮廓。
- 160ms 的背景/边框过渡；prefers-reduced-motion 时关闭过渡。无光晕、无 backdrop-filter、无大面积动画。

## 交互检查步骤

对每个方向执行同样操作：

1. 关闭自动记录，确认“未保存”；保存后显示“已关闭”，现有清单不变。
2. 搜索“番茄”得到 1 条；搜索“榴莲”得到空状态；清空关键词恢复 3 条。
3. 打开“模拟查询失败”再查询，得到错误提示且旧结果保留；关闭后查询恢复。
4. 清空角色 ID，查询或重试应提示补填；填回后重试显示排队状态。
5. 空表单提交更正，检查错误与焦点；填入演示评价、选择喜恶，提交后列表更新。
6. 在长文本输入内容，收起再展开“更正口味评价”，检查输入、选项和字符计数保留。
7. 重置并取消，输入保留；确认重置后示例恢复。
8. 用 Tab/Enter/Space 完成折叠与表单操作，检查焦点；调整为 1440 / 1024 / 390px 检查换行。

## 三套方向比较

| 方向 | 可读性 | 信息密度 | 扩展性 / 取舍 |
| --- | --- | --- | --- |
| A | 深灰低刺激，操作突出，侧栏解释明确 | 中等 | 适合配置型页面；长列表扩展到主区，窄屏侧栏下移 |
| B | 浅雾紫与深正文，卡片分组柔和 | 中等，宽屏并列提高利用率 | 适合混合配置与查询；模块尺寸差异大时应使用显式栅格，不用瀑布流 |
| C | 行分隔和标签结构明确，扫读效率高 | 最高 | 适合多字段与批量结果；长说明需另留区域，避免压缩成难读小字 |

选择建议：长时间深色使用选 A；偏好柔和浅色选 B；高频运维与大量参数优先 C。最终接入须等用户选定，第二阶段才做组件和视觉整合，第三阶段才讨论功能分类。
