# 角色删除与恢复

入口为管理面「排错与管理 → 删除相关」，全部接口要求 `admin` scope。桌面及手机协议未改变。

列表包含角色卡和已无角色卡的专属数据。按角色 ID 计算路径；展示名不作为用户 ID 或路径。确认窗默认勾选「同时清理该角色相关数据」，可取消并只删除角色卡。保留模式下，同 ID 重建会重新读取保留的数据。

预览显示文件数、字节数和阻断原因。提交需要输入相同角色 ID，并携带预览指纹；数据变化后必须重新预览。当前角色、默认角色、仍在群聊或定时任务中的角色、未结束工作会话，以及运行中的对话和后台处理会阻断操作。需要先切换角色或解除引用，不自动改写共享群聊历史。内置角色卡不可删除；专属素材仍被语音配置或其他角色引用时也会阻断。

清理采用明确的 DataPaths 路径白名单，包括私有及旧层角色卡、角色专属记忆与运行状态、任务工作空间、authored 文件、专属模型目录和头像。用户全局数据、共享素材、其他角色及混合关系/群聊历史保留。目录联接、符号链接及越界路径拒绝自动清理。

删除将内容移入 `character_cleanup_archive_dir()`，保存操作清单并刷新资产 registry；移动失败时回滚，失败状态保留在记录中。页面支持恢复，目标已有同 ID 内容时拒绝覆盖。备份不自动过期，本页没有永久清空功能；归档属于私有运行数据。可读观测为列表、预览及删除恢复记录，不返回本机绝对路径。

接口：`GET /character-cleanup`、`GET /character-cleanup/{char_id}/preview`、`DELETE /character-cleanup/{char_id}`、`POST /character-cleanup/restore/{operation}`。删除请求包括 `include_data`（严格布尔值，默认 true）、`fingerprint`、`confirm_id`。

验收使用隔离安装的测试角色，覆盖删除与恢复、保留数据、双层卡回退、过期预览、引用阻断、失败回滚、同 ID 冲突及非法路径。真实运行中的角色清理未执行。
