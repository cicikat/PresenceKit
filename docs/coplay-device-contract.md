# 292-B：陪玩设备采集合同 v1

远程部署的采集器只在用户电脑运行。后端保留会话、接收和分析，不读取服务器屏幕、Steam 注册表、进程或用户存档目录；本地部署继续原有路径。桌面完全退出后采集不可用，不承诺云端拉起本机进程。

## 传输与授权

桌面复用现有视觉 runner 的单进程生命周期与 HTTP 客户端，通过两个 POST 路由交互，不增加 WS 帧。`/coplay/device/poll` 和 `/coplay/device/result` 同时要求 activity、sensor.write、ws.desktop；移动端无 ws.desktop，不消费这条链。

请求带 runner 生命周期随机生成的 client_id；服务器将其与 token label、owner、当前角色、陪玩启用轮次和配置指纹绑定。poll 返回单次 lease_id、protocol_version=1、角色、配置版本、有效期20秒、最多100个白名单游戏、Steam库路径与图像大小上限。配置仅由管理员已有 coplay 设置维护，不接受模型或 result 改写。一个角色同一时间只接收一个未过期采集租约，poll不无限堆积。

result 必须匹配租约、client_id、token身份、角色及配置指纹，采集时间不早于租约发出、不超20秒且未来误差最多5秒。一次性消费，重复结果不得重复推进会话或分析图像。新连接、角色切换、disarm、配置变化、服务停止或权限撤销拒绝旧结果。采集端在采集前和发送前检查停止、锁屏和授权版本；没有离线补发队列。

## 最小数据

只上报匹配白名单/Steam的单个 game_id、游戏名、是否前台及可用状态；不上传完整进程清单、原始窗口标题、存档正文或文件路径。存档最多上报本轮配置游戏的 change 布尔值，客户端只保留元数据指纹。

截图另受既有本地按需截图许可和后端看屏幕开关约束。只有被识别游戏确在前台且桌面解锁时才采集其窗口；无法证明前台归属或捕获失败时上传无图状态，不用其他窗口或主屏幕冒充。JPEG最大1280边、1MiB解码字节；后端核验图片尺寸、格式及像素上限，图像仅用于本次分析，不落原图台账。

客户端离线、锁屏、授权关闭、采集失败、报告过期均只代表不可用，不能据此认定游戏退出。只有新鲜且明确可用的报告能驱动 armed→active 或 active→closing；切换游戏先结束旧会话，待closing完成后重新识别。图像分析按冻结的uid/char/game执行，异步结果在提交前再次核验会话和配置。

## 观测与验收

复用 GET `/coplay/state` 增加 collection：采集来源、fresh/blocked原因、授权、报告年龄、设备在线/租约状态及接收/拒绝计数，不返回图像、路径或进程名。后端管理面复用已有陪玩设置/状态，无新增部署开关；设备本地沿用sensor与按需截图许可。

相关回归覆盖远程零OS采集、scope、错误身份、角色切换、配置变化、去重、时间与大小、锁屏/撤权、断线和游戏切换。本地部署回归保持通过。Windows真实游戏与远程服务器收发单列实机验收，不以合成结果宣称完成。
