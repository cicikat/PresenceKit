# 角色行为页面的分区恢复（2026-11-15）

此前的恢复只覆盖已拒绝的片段请求。`allSettled` 仍等全部片段结束后才移动任何表单；一个请求长期不返回就能让整页只剩标题，兜底重试也不能及时显示。原浏览器回归只注入了 HTTP 503，没有覆盖悬挂请求。

另外确认了进入顺序缺陷：功能总览/自主活动会间接准备共享表单，但此前没有先加载角色行为本身的 shell。第一次直接进入角色行为时，片段加载覆盖了提前移入的表单，sections 注册表仍保留旧节点，之后也不会重建。新回归先通过实际导航进入功能总览，确认共享表单已挂载，再点击角色行为；修复前第二次邮件控件断言失败，修复后必须保留同一组控件。

## 修复

- 各来源片段独立组装、独立启动数据读取；后到的片段按固定栏目顺序插入，保留已显示控件及其监听器。
- 间接准备共享表单时先挂载其所属页面 shell，避免首次直接导航清空已组装的页面。
- 片段读取含响应体限时 8 秒；JSON GET 含响应体默认限时 10 秒，保留调用方取消与可选超时覆盖。写请求保持原确认语义，未把超时当成保存失败或成功。
- 失败明确列出来源和错误并提供重试。不完整但返回 200 的片段也可重取；同一代并发进入复用初始化任务，重试不会重复移动控件或重读其他模块覆盖草稿。
- 对应模块初次读取期间暂时禁用表单；成功或局部失败后移除临时 fieldset，保留原节点。邮件模块等待它启动的并行读取结束，避免“可以编辑”后仍有旧读取回来覆盖输入。
- 布局恢复递增代际，旧任务不再重新组装新布局；普通页面的初始化异常也提供可见错误入口。
- 页面 loader 按需引用，缺少无关模块脚本不会让全部导航在构造 loader 表时抛异常；角色行为的子 loader 同样隔离。
- 更新 core、i18n、setup、layout 及片段缓存版本为 `behavior-recovery-20261115`。

未修改设置 schema、scope、后端行为或跨仓协议，仅影响后端管理面；不扩展到桌面/手机客户端。
