# 饮食清单与明确口味（F4）

## 数据与更新

现实 owner 对话在发送回复前只把候选用户原话写入本地 inbox；发送后 slow queue 调用独立 `food_extract` 路由抽取。模型不直接写清单：程序检查原话子串、食品名称、明确评价与吃过证据。假设、计划、第三方评价不计入。用户/角色隔离，重复消息幂等；按证据时间显式覆盖评价，旧任务晚完成不能覆盖新评价。

仅记录喜欢、不喜欢、暂时不想吃、明确吃过；吃过不代表喜欢，暂时拒绝不覆盖长期评价，也不自动过期为喜欢。口味仅接受用户明确表达，不从某道菜评价推测一般口味。食品名称保留用户实际写法，不猜测同义名或店家归属。

`recorded_eaten_count` 是已记录的明确餐次，不是真实终生次数。同日同食品未说明餐次时保守合并；明确早餐/午餐/晚餐分别计数。重述不重复计数。不从“常点”、摘要或角色猜测生成次数。

数据库由 `get_paths().food_memory_db()` 提供；jobs 与 events 都带 uid/char_id，写入追加 provenance。失败保留 inbox，单任务最多三次自动尝试；下一次对话触发处理，管理面可重试。重启不主动发起模型调用。

## 角色与控制面

`read_food_preferences(query, limit)` 按需查清单，默认20项、最多50项。工具说明要求在推荐吃食、核对拒绝或口味改变时查询；最新用户表达优先于旧记录。不会常驻注入具体食品。

启用时 profile 的 `pref.food` 不进入常驻偏好投影，新 profile 抽取也不把具体食品写入习惯摘要；历史原文和情景证据不删除。`5.2_food_tastes` 只注入明确口味及证据时间。混合习惯条目在投影侧去掉带饮食主题或清单食品名的句/分号分句，保留其余原文；identity 投影去掉清单具体食品所在分句，保留泛化的话题描述。关闭后恢复原投影。不是全文历史删词或抹除原始证据。

管理面模型路由包含 `food_extract`，遵循现有 category/default/chat fallback，建议选择小模型；调用20秒、SDK零重试。工具页提供热更新开关、effective route、按角色查询、更正和重试。开关默认开启；关闭恢复原 profile 投影和抽取行为，已有清单保留且仍可按需查询。

API：`GET/PUT /settings/food-memory`、`GET /observability/food-memory`（state.read）、`POST /settings/food-memory/correct` 与 `/retry`（admin）。更正必须提供实际用户原话并通过同一校验，不能直接制造喜欢/不喜欢。清单为后端共享工具能力，无新增桌面/手机设置合同。

## 历史迁移与验证边界

`scripts/migrate_food_memory.py --uid <owner> --char-id <character>` 默认 dry-run，读取现实用户原始台账、短期原文与符合历史角色归属的日分日志；排除梦境/外部来源、墓碑、低置信语音及不明来源。默认20条，显式 `--limit` 最多5000条；原台账 turn_id 优先去重。`--apply` 先备份候选与数据库再幂等排队；`--process` 必须同时 `--apply`，运行独立抽取路由并报告 completed/pending/not_enqueued/events，排队不能冒充完成。原历史不改写。

2026-10-07 已对真实历史主角色执行迁移：100条候选抽取完成，失败0，采纳24条事件（17条实际吃喝证据、5条评价、1条明确口味、1条暂时拒绝）。候选与旧数据库已备份；重复排队未新增事件，概要投影不含清单具体食品。记录数不是终生吃过次数。

定向回归覆盖覆盖顺序、隔离、重试、去重、否定/假设、暂时拒绝、口味证据、开关与权限。隔离浏览器验证实际静态页、路由保存、开关回显和更正；真实小模型历史抽取已验收，真实陪伴角色推荐行为仍 observe。
