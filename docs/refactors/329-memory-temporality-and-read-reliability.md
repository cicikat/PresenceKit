## 事实合同与边界

`profile.temporal_facts` 保存 topic/value/source_id、occurred_at/recorded_at、valid_from/valid_to、
kind/source、status 和 superseded_by。状态为 valid/expired/superseded/pending。
发生时间优先，等时才比较来源权威；同强度等时矛盾返回未知，不按最后入库取胜。
新事实过期或撤回后不会把更早的失效状态重新升级为当前；派生压缩永不成为当前证据。
保留证据被 tombstone 时，已存当前断言在读取侧失效，不回退到更早住处；证据服务不可用时返回未知，
不偷偷退回未版本化的旧地点/职业。只核对各主题当前候选的来源，历史量增长不导致逐条查原事件。
计划、猜测、引用、问题句与不明确的表达不会直接覆盖当前生活状态。

明确自述快速路径保守支持居住、工作和取消购买；通用 claim/裁决合同允许受信 writer 提供其他主题。
它不是通用自然语言理解器，含糊、隐含或未支持的表达仍需证据细查，不能据此宣称所有生活事实均已自动结构化。
历史兼容投影每个主题词最多查询 32 条原始用户事件，过滤隔离来源、群/Stage 通道和低置信语音；
不扫描所有私人文件，不自动改造整批旧资料。完整历史仍由既有事件/记忆工具读取。

当前事实进入既有预算内 profile 层；冲突的 profile 自由事实只在本轮投影排除，派生召回保留原文但
显式标为历史，不能压缩后重新成为当前事实。原始存储始终保留。
`GET /memory/{user_id}/temporal-facts?char_id=...` 使用 `memory.read`，只返回来源 ID、时间、状态和裁决原因，
不返回私密正文。现有 profile 层观测也带同一裁决元数据。

缓存键包含工具名、规范化参数、uid/角色/origin、配置/注册授权摘要与相应文件/SQLite WAL 版本。
只缓存成功且读取前后版本一致的结果；并发更新、权限变动、失败、未知结果不复用。
不同工具、record_id、offset、cursor 均独立。其他工具执行后保守清空轮内缓存。
