# 聊天恢复与正文清理（工单56，2026-11-15）

## 已实现

桌面失败、未收到回复或执行结果未知且仍有原载荷时，以红色感叹号提供显式重发；停止旧观察、生成新请求 ID、复用原用户气泡，保留输入区的新草稿及附件/引用。请求仍在执行时按钮不可重复提交。手机保留既有可重试失败按钮，移除不执行重发的旋转补读图标及气泡下所有投递状态说明；排队长按取消和连接头像的诊断入口保留。

桌面流已有可见正文时，本地等待结束不能使随后的 HTTP 错误被忽略。失败回执只移除空流，不移除可见正文，并关闭光标。保留关联映射，晚到 canonical 回复原位替换部分正文并清除失败按钮。缓冲式中转若失败前已收到纯文本，后端只投递已去除思考和工具协议的正文；仍返回失败、保持失败回执，不写成功记忆、不执行不完整工具、不自动重放。

历史根因：用户尾注的识别曾依赖后面必须有角色回复，未回复用户消息在块结尾的 speaker/turn_id 被当正文。后端修复该边界，两端同时兼容旧服务器返回的末尾 writer footer；普通正文引用与结构化关联键保持有效。
