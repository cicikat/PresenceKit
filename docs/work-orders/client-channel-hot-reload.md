# 客户端通道热更新

## 目标与根因

桌面、手机与微信已有热更新消费者；QQ 的通道、回调和连接任务只按启动时配置创建。
需要由 startup 持有始终存在的 QQ supervisor，保存开关 / 连接后立即协调，不依赖重启。

## 本单范围

- [x] QQ supervisor：开启连接、关闭断开、地址变更重连；standalone 保持阻断。
- [x] 旧连接排队消息与已开始回合隔代拒绝投递；关闭不取消已开始回合的记忆落盘。
- [x] 文本 / 图片 / 语音 / 工具调用统一拒绝失效连接；待响应请求在断开时结束。
- [x] 两个管理 API 立即 apply 并返回真实 effective state；桌面、手机、微信原热更新保留。
- [x] 页面提示、静态资源版本及控制面 / 生命周期文档同步。
- [x] 相关回归、换行 / 差异检查、真实浏览器验收，独立提交。

## 验收边界

不新增配置开关、持久状态或第三方桥认证协议；QQ connection 状态只表示 OneBot 连接，
不等同于账号登录 / 实际消息送达。不改桌面 / 手机客户端协议或 QQ 群聊、访客准入。
本轮代码升级需重启后端一次；升级后管理开关与 QQ 地址保存均热生效。

测试用可控连接验证启停 / 重连 / standalone / 旧代回合拒发，再用真实管理 API 与浏览器
验证保存时进程不变、状态一致。实际手机、QQ / 微信两轮收发单独验收。

## 删除候选

本单移除 QQ startup 条件分支及“QQ 必须重启”的过期提示 / 测试断言。
message_queue 其他使用场景与第三方桥安装配置不清理。

## 完成证据

支持环境 Python 3.12：106 项相关回归通过，包含本机真实 WebSocket 的连接、关闭、
重新开启与绕过环境代理，以及旧代排队 / 运行回合的文本、媒体、工具拒发。
真实管理 API 验证 QQ 热启停与地址保存时进程不变；采用未监听的本机端口避免外部
投递，结束后恢复原连接配置与原关闭状态。管理面硬刷新后保存表单显示热生效提示，
QQ / 微信与桌面 / 手机状态区显示实际运行值。JS 语法、差异与 LF 检查通过。

observe：真实 QQ / 微信两轮私聊及原生桌面 / 手机投递仍需单独验收；本单测试和
WebSocket 连接不替代账号 / 设备实际收发。无跨仓客户端设置或消息协议变更。
