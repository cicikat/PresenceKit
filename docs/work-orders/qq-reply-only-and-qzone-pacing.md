# QQ 回复隔离与空间请求节流

## 范围与验收

- [x] QQ 默认只回复 QQ 输入的当轮对话；手机、桌面、主动消息不广播到 QQ。
- [x] 管理面提供 reply_only / muted / all 热设置与有效状态；文字、语音、图片受同一收口控制。
- [x] QQ 空间保持独立授权与读取，跨角色共享请求间隔、写入冷却、失败退避；禁止自动重试写操作。
- [x] 复用相关回归，补并发、热切换、迟到任务与限频测试，管理面浏览器验收。
- [x] 检查差异、换行、敏感内容并独立提交。

限频用于降低请求集中和重复操作，不模拟人类身份，不保证免封号。真实 QQ 回复、真实空间评论/点赞不由 fixture 验收替代。手机/桌面接口、队列与协议不变。

## 审计发现

QQ 在线即参与 fanout；空间默认 120 秒扫描最多两位作者共十条帖子评论，每业务请求另查登录账号，缺少跨角色请求节流与失败退避。桥内 fallback/保活仍可能产生额外请求。

删除候选：旧自动 QQ 广播模式可在使用确认后退役；本单保留显式 all 兼容选择，不执行未授权清理。

## 最终范围与证据

按追加要求，每轮只查询一个已配置关注用户最近 5 条说说，不隐式追加机器人账号；评论每轮最多两帖轮换。继续使用当前目标。扫描策略 revision 更新，旧候选作废，新策略重新建立基线。

本地 ignored 配置已设 reply_only、扫描 600 秒、请求间隔 3 秒、写冷却 60 秒；不变更其他客户端或空间授权。源码加载需要正常重启后端一次，随后管理面热设置。
