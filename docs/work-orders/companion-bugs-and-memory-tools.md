## F4 · 吃食清单与口味概要（设计建议）

推荐独立结构化清单，而非自由文本文件：具体食物/店家、状态（喜欢/不喜欢/暂时不想吃/吃过未评价）、用户原话来源、时间、原因、可选临时截止时间。口味概要只记录辣度、油腻程度等倾向，标记推测与证据时间。

理由：现有冲突证明“曾常点”与“现在想吃”需要分别建模；纯摘要容易丢失否定、时间和来源。暂时拒绝不能直接变成永久讨厌，历史点单也不能直接变成喜欢。

- [ ] 明确“概要”对应 profile preferences/important_facts/identity 等自动投影；禁止具体食品进入常驻偏好概要，历史情景原文保留供按需查询。
- [ ] 增加查询/更新饮食清单工具；吃饭讨论按需读取，最近明确拒绝优先于旧常点事实；无新证据不自动恢复推荐资格。
- [ ] 角色推测不能升级为用户确认；记录旧新状态、证据与 provenance，提供管理面清单和更正观测。
- [ ] 历史迁移先 dry-run，展示候选和冲突；备份后小批次幂等迁移，不删除原始聊天/情景证据。
- [ ] 回归：常点后拒绝、仅今天不想吃、改变口味、同名不同店、推测、跨角色隔离；真实吃饭对话不再机械推荐已拒绝项目。

设计待定：建议“角色维护、用户可查看更正”，暂时不想吃在有效期内停荐；未给期限时保留待确认状态，不擅自设置永久讨厌。
