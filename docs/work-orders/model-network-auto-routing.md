# 模型出站网络自适应工单

背景：`/mobile/chat` 复用后端模型客户端。直连模式明确忽略环境代理；若系统 DNS 将模型域名解析到代理 Fake-IP，直连可能失败并使聊天返回 503。模型地址由 preset 的 `base_url` 配置，不在代码里固定。

- [x] 核对手机聊天入口、模型出站连接、现有 `/proxy` API 与管理面入口；保留其他未提交文件。
- [x] 为模型请求增加独立连接模式：跟随全局设置（兼容旧配置）、自动、直连、代理。自动模式每次请求检查目标 DNS；命中 Fake-IP 或解析失败时用已配置代理，其余走直连。代理地址仍由本机忽略跟踪的 `config.yaml` 和管理面维护，不写死运行地址。
- [x] 管理面“代理与中继”显示并保存模型连接模式，明确自动模式所需代理地址及直连失败时的手动切换入口；热重载模型和视觉客户端。
- [x] 验证 Fake-IP、真实地址、DNS 变化、缺失代理地址、旧配置兼容；跑相关测试、换行和差异检查。
- [x] 更新控制面文档、静态版本，完成浏览器可见结果验收；真实模型网络与手机端验收分别记录。
- [x] 本工单独立提交。

验收记录：隔离管理面浏览器覆盖「代理与中继」显示/保存自动模式、缺 HTTP 代理地址拒绝保存，以及系统状态摘要展示当前模式。真实模型出站网络与手机聊天未在本机实测，记为 observe。

删除候选：现有全局代理开关与模型专用连接模式并存，后续可在单独工单审计和合并重复的模型代理选择函数；本工单不清理其他出站工具的代理策略。
