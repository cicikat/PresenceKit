# 灵感记录：系统可玩性与拓展性改进构想

本文档用于记录关于 PresenceKit (Emerald-presence) 系统的长期演进构想，重点围绕**可玩性（互动深度与游戏化）**与**拓展性（架构解耦与二次开发支持）**展开。

---

## 一、 可玩性（Playability）提升构想

### 1. 情绪花园协同与物化玩法 (Co-op Garden & Item Pressing)
*   **构想背景**：当前 `core/garden` 主要由调度器自动浇水，或由角色通过内部工具维护，用户处于单向被动观测状态。
*   **具体方案**：
    *   **共同种植与许愿契约**：允许用户在前端向花园“赠送花肥”或“种下带有留言的许愿种子”（通过 Path C 工具或定制接口）。角色会感知该事件，并在后续对话中表达感谢或对种子的期待。
    *   **花卉物化交互**：收获的干花（`dry`）或花瓶（`vase`）不应只是只读数据，可解锁“玩家/角色共同将其制作为书签、香薰、干花茶”的合成事件。
    *   **情境软提示（Soft Hint）**：合成出的实体道具（如“向日葵干花茶”）记录在用户资产中，使用时（如用户在界面上点击“与他喝茶”）会向 LLM 注入临时的 `soft_hint`（“角色正喝着用户送的花茶，心情感到愉悦”），改变语气。

### 2. 梦境系统分支分歧与清醒度 (Lucidity Meter)
*   **构想背景**：Scenario 模式属于线性脚本体验，Mirror 模式对隐性状态的映射也是自动发生的。
*   **具体方案**：
    *   **抉择分支与赛博身体状态耦合**：在 Scenario 剧本中引入多分支选择（Choice Envelope）。用户的交互选择改变 `body_state`（敏感度/紧张度/亲密距离）的走向，进而决定梦境的最终结局和生成的“梦境明信片”信件模板。
    *   **清醒度（Lucidity）刻度设计**：梦境中加入清醒度指标（0-100）。
        *   **高清醒度**：角色在梦境 Prompt（D0-D10）中保有更强的 lucid 自知，他会温柔地戳破“这是你的一场梦”，甚至能聊及现实发生的事，不打破沉浸感但保留现实纽带。
        *   **低清醒度**：角色完全被世界规则（World Ruleset）同化，呈现纯粹设定中的人格（例如纯冷酷的吸血鬼或高傲的法师），提供更极端的 RP 扮演乐趣。

### 3. 感官联觉与现实物理联动 (Sensory Synesthesias)
*   **构想背景**：Apple Watch、手机传感器和桌面截图等虽有接入，但缺乏对用户实时“环境氛围”和“操作意图”的敏锐捕捉。
*   **具体方案**：
    *   **音乐与游戏状态感知**：通过 MCP 或桌面客户端获取用户正在播放的音乐（如 Spotify/网易云）或正在运行的 Steam 游戏。当用户在玩“高压/魂系”游戏时，桌宠可在桌面进行特定的支持性动作（如握拳、递茶UI）；若听忧伤音乐，角色可主动开口询问是否心情不佳。
    *   **具身硬件（Intiface）的温和解冻**：在 `user_hidden_state` 和 `mood_state` 高度契合（如 gentle/Daisy 状态）且在受保护的 Dream Session 中，允许解冻受控的硬件物理反馈，作为虚拟情感物理化的延伸。

### 4. Stage 跑团与共玩模式 (Co-play TRPG)
*   **构想背景**：Stage 仅实现了多角色聊天接话与关系摘要投影。
*   **具体方案**：
    *   **轻量 TRPG 仲裁器**：在 Stage 架构上接入简易规则书，角色卡持有技能属性（力量、魅力等）。
    *   **共玩体验**：用户与在场的多个 AI 角色开启文字冒险跑团，Stage 负责计算骰子和场景演变，角色根据性格和彼此的关系（`char_relations`）动态决定行动，共同编写故事。

## 二、 拓展性（Extensibility）提升构想

### 1. 统一事件/感知总线 (Unified Event Bus)
*   **构想背景**：`docs/interaction-event-model.md` 中的 Envelope 理念尚未全面重构到现有主业务逻辑，很多触发器和数据流高度耦合。
*   **具体方案**：
    *   实现全局 `EventBus`，定义统一的 `EventEnvelope(realm, kind, lifecycle, payload)`。
    *   所有外界输入（聊天输入、Watch 心率、传感器 Tick、桌面截图、外部 Webhook 等）均转换为统一事件投递到总线。
    *   Autonomy 调度器和 proposer 只需要订阅对应的 Event 类型，与入口端点和物理通道彻底解耦。

### 2. MCP 动态插件热拔插与安全沙箱 (Dynamic MCP Registry)
*   **构想背景**：当前 MCP tools 仍需管理员在 backend 配置文件中静态添加并授权。
*   **具体方案**：
    *   **插件市场模型**：在 Admin 页面支持通过 URL 或包名一键注册新的 MCP Server。
    *   **声明式权限沙箱**：MCP Server 可在 manifest 中声明其需要的权限域（如 `read:schedule`, `write:music`），系统根据声明并结合危险模式闸门进行精细化的安全隔离，防止第三方不可信工具获取全量系统控制权。

### 3. PresenceKit Client Protocol v1.0 与 SDK 开放
*   **构想背景**：Tauri 桌宠目前采用 legacy 冻结版的 v0.1 WS/HTTP 协议，开发新客户端门槛较高。
*   **具体方案**：
    *   设计并发布标准的 Client Protocol v1.0 规范，提供标准的 OpenAPI 接口描述和清晰的 WebSocket Segmented 帧规范。
    *   开发轻量级的客户端 SDK（Python / JS / Dart），方便社区为系统定制 **3D/Live2D 具身桌宠**、**微信小程序挂机端** 或 **VR/AR 虚拟空间伴侣**。

### 4. 链式可插拔记忆整合管线 (Pluggable Memory Consolidation)
*   **构想背景**：慢队列的固化管线（summarize -> reflect -> consolidate）路径目前是硬编码的，不便于添加自定义的记忆分析引擎。
*   **具体方案**：
    *   将 `fixation_pipeline` 重构为管道过滤器设计（Pipeline Pattern），每个记忆处理逻辑作为独立的 Filter 注册。
    *   支持动态挂载自定义的 Filter。例如：挂载一个“人物关系图谱提取器”，将对话自动沉淀为关系图数据库；或挂载“用户情绪波动图表生成器”，使记忆整合更加模块化和易观测。
