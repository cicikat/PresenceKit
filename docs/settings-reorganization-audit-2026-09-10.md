# 管理面板与桌面偏好重整审计

日期：2026-09-10。状态：审计完成，重整方案为 roadmap，尚未施工。

## 1. 结论

建议采用用户提出的职责划分：桌面偏好集中管理本机界面、桌宠、连接和当前角色切换；后端管理面集中管理模型、生成行为、工具能力、授权策略和服务配置。

建议一级导航为「概览、功能与行为、服务配置、创作、观测、运维与调试」六项。工具细分和配置填写是二级页面，不再各占一级分类。必须补上“对话与主动行为”的归属，否则从客户端迁出的思考、对话风格、主动间隔仍无处安放。

这里的“客户端只负责 UI”指设置职责，不是删除它已有的截图采集、Tauri 动作执行、播放、确认、任务停止和通道订阅。执行所需的本机同意与操作反馈仍留在使用现场。

## 2. 范围与证据边界

- 核对后端导航、页面片段、主要设置 JS、设置路由、控制中心状态投影，以及桌面偏好组件、API 包装、相关 Rust 转发与活动页设置消费者。
- 参照 `docs/feature-control-surface.md`、`docs/three-repo-interface-catalog.md` 和相邻桌面仓库 `docs/settings-control-audit.md`；发现文档旧入口时以源码为准。
- 这是源码与信息架构审计。浏览器实测未完成，本轮没有登录运行中的面板、验证实际部署状态或进行真实桌面操作，也没有修改产品 UI。
- 手机只做共享接口影响初筛，不宣称完成手机全量设置审计；后续若调整 scope、设置接口或播放语义，必须补查 Flutter/Android 消费链。
- 未读取生产密钥或用户记忆。仓库已有未提交改动不属于本次审计。

## 3. 已确认的问题

| 发现 | 源码证据 | 影响与建议 |
|---|---|---|
| 导航过度分散 | `admin/static/index.html` 有 39 个侧栏 `data-page` 入口；`admin/static/pages/` 有 26 个 `observe-*.html` 片段 | 两个数字口径不同，不能相加；其中部分观测片段已经不是侧栏独立入口。需要按任务合并入口，而不是逐接口建页 |
| 基础配置与高级配置混装 | `setup.html` 同时包含聊天模型、所有者、Embedding、邮件、纪念日、日记路径和陪玩名单；`runtime-config.html` 混合代理、生成参数、危险模式、观测实验开关、表情包等 | 分成配置摘要、配置详情、功能策略和诊断实验 |
| 只读观测有写控件 | `observe-prompt.html` 含 `savePromptAblation`、`saveOutputSegmentEnforce` | 分段兜底移至对话行为，提示词消融移至运维实验；观测只负责读取 |
| 同一功能跨数页 | MCP 页含启停、连接、白名单、调用控制台、LLM 请求调试；唤醒页含配置、运行和 Prompt | 每项设一个主要编辑归属，其他位置仅摘要和带上下文跳转 |
| 创作与执行策略混合 | `character.html` 同时有角色正文、能力绑定和模型绑定 | 正文留创作；能力绑定进入功能详情，模型绑定进入模型配置；创作显示绑定摘要和链接 |
| 客户端“偏好”能改后端全局行为 | `preferencesInfoArchitecture.ts` 的 models/capabilities/characterChat；Rust 的 `patch_proactive_gap`、`patch_presence_nag` 写 `/scheduler/config` | 不是单纯本地展示，需迁走编辑入口；存在感弹窗开关当前也不是本地通知偏好 |
| 已有聚合基础但仍多入口 | `overview.js` 读取 `/admin/control-center/effective-state`；`loadSystemDiagnosis()` 聚合资源、运行、触发器和契约 | 复用投影和诊断数据，不另建一套状态真值 |
| 状态投影与执行规则可能不一致 | `core/control_center/effective_state.py::_tool_loop_row` 在全局 configured=false 时直接 effective=false；`core/tool_dispatcher.py::_effective_tool_loop_enabled` 允许角色 `on` 覆盖 | 静态确认的逻辑冲突；部署是否触发未实测。集中展示前应补“全局关、角色开”的回归并修正投影 |
| 文档的权限描述有漂移 | 控制面文档称全局状态投影 admin-only；`admin/routers/control_center.py` 路由声明 `require_scopes("state.read")` | 施工前核对完整挂载鉴权并同步文档；不能因 URL 含 admin 就认定 admin-only |
| 中文术语不统一 | `i18n.js` 中文值有“已配置 Servers”；页面存在 Presets、Routing Profiles、policy 等混排 | 使用语义翻译键和统一术语，技术标识放详情，避免替换英文片段来拼中文 |

## 4. 建议的新管理面架构

| 一级区域 | 默认页 | 下钻内容 |
|---|---|---|
| 概览 | 待配置项、阻断项、最近异常、快捷入口 | 跳对应功能、配置或记录，不提供另一套编辑表单 |
| 功能与行为 | 所有主要功能的统一控制列表；按工具、感知、主动行为、对话输出分组 | 每项的子开关、范围、额度、角色覆盖、超时和确认策略 |
| 服务配置 | 文本模型、视觉、OCR、语音合成、向量检索、MCP、邮件、代理、中继、数据源、通道等配置摘要 | 各服务连接填写、模型连接与方案、角色模型绑定、测试和保存 |
| 创作 | 角色卡、现实设定、梦境设定、素材 | 世界书、剧本、预设文本、关系事实、用户称谓与纪念信息；后者是用户资料，需明确标识 |
| 观测 | 运行总览及五个主题入口 | 对话与生成、工具与任务、主动行为与通道、记忆与角色状态、调用与资源 |
| 运维与调试 | 服务维护与诊断入口 | 访问凭据、备份恢复、数据管理、日志、兼容性检查、调试实验、受控调用控制台 |

“服务配置”只显示摘要和跳转，符合用户设想。例如：语音合成——已填写连接，最近一次合成失败，查看配置。必须区分“配置齐全”“已测试可用”“未测试”“测试失败”；缺少非必需服务不应全站红色告警。

工具总页应覆盖真实可执行工具和能力族：内置工具、外部工具、文件/工作区、浏览器、电脑操作、手机操作、联网搜索等。感知、调度、陪玩、私下往来、输出行为在同页分组或同区域页签，不强行称为工具。日志记录与实验开关归运维。

## 5. 统一开关的语义

建议一行显示：中文名称｜启用控件｜实际可用状态｜原因｜作用范围｜设置｜记录。

示例：浏览器操作｜开启｜暂不可用｜执行服务未连接｜全局策略｜设置｜记录。

1. 展示配置是否开启、当前是否可用、角色是否允许、依赖是否就绪；“最近没有执行”不等于不可用。
2. 分清执行总闸门、模型可见工具范围、多步调用方式。关闭多步循环不等于关闭所有工具；白名单不是执行授权。
3. 当前角色覆盖可改变部分全局默认。先标注“全局默认”和“角色覆盖”，不要把默认开关写成绝对总闸门。
4. 如果需要新增“任何角色都不得绕过的工具总开关”，这是后端执行契约变更，必须覆盖普通工具路径、多步循环、自主任务、MCP 和在途任务语义，单独施工。
5. 配置不足时仍能跳去补配置；关闭功能不清空连接。停用是否影响在途任务、是否需重启必须逐项说明。
6. 角色级选项使用“跟随全局 / 开启 / 关闭”；模型绑定的“跟随全局”仍用既有清除语义，不误把名为 default 的真实方案当成继承。
7. 不存在真实运行时开关的项目只展示状态，不能伪造开关。例如 Embedding、部分通道、冻结中的集成。

## 6. 桌面设置迁移清单

| 当前项 | 建议位置 | 迁移注意 |
|---|---|---|
| 全局模型方案、角色模型绑定 | 服务配置 → 文本模型 → 方案与角色绑定 | 沿用既有 routing profile 与角色覆盖，客户端不保留写入口 |
| 思考模式、主动消息思考、预算 | 功能与行为 → 对话生成 | 思考生成与已返回思考的存档、展开显示是不同概念 |
| 聊天模式、对话风格、多消息、段落兜底 | 功能与行为 → 对话输出 | 多气泡是后端发送策略，不因看起来像 UI 就变成本地设置 |
| 多步工具循环、类别、排除项、步数和超时 | 功能与行为 → 工具调用 | 保留模型兼容性、角色覆盖与执行闸门说明 |
| 电脑危险模式及期限 | 功能与行为 → 电脑操作 | 当前 `get_meta_mode/patch_meta_mode` 实际转发后端 `/system/meta-mode`；现场执行确认与紧急停止保留 |
| 浏览器能力策略 | 功能与行为 → 浏览器操作 | 管理配置与实验任务分开，实验控制台归运维 |
| 视觉感知后端策略 | 功能与行为 → 屏幕感知 | 本机截图同意与采样参数是 Rust 本地状态，不能直接搬成后端配置；可留“连接与本机访问”，或改成首次使用授权流程 |
| 存在感弹窗触发、主动最小间隔 | 功能与行为 → 主动陪伴 | 当前二者写 scheduler；若保留本机静音，应明示“仅此设备”，不能复用全局字段 |
| 世界书、提示词预设的启用组合 | 创作 → 现实设定 | `PromptAssetsSettings` 需拆开，只把当前角色切换留桌面 |
| 角色头像上传 | 创作 → 角色卡 | 当前上传是后端角色头像，不是本机装饰；本机头像可见性等展示项可保留 |
| 经期日期、用户称谓、纪念日 | 创作 → 用户资料 | 是输入内容，独立于系统功能授权；可从聊天资料入口快捷录入 |
| 语音服务、声音和生成策略 | 服务配置 → 语音合成 | 自动播放/音量/静音可留客户端，但当前部分自动播放字段落后端，必须保留既有作用范围或另做本地化迁移 |
| 界面、语言、主题、字体、背景、布局与 Design Mod | 桌面 → 界面 | 保留既有本地状态与多窗口同步 |
| 桌宠形象、缩放、鼠标、漫游、涟漪；通话呈现 | 桌面 → 桌宠与互动 | 只保留呈现参数；服务能力和授权仍归后端 |
| 后端地址、令牌、连接状态、打开管理面板 | 桌面 → 连接 | 复用现有本地 bridge；不把管理密钥塞入普通客户端配置 |
| 日记目录选择与手动同步 | 桌面 → 连接与本地资料 | 目录属于本机，不应由后端编辑；服务端读取路径单独归数据源配置 |
| 陪玩启停、通话开始/结束、玩耍入口 | 对应使用场景 | 属于会话操作，保留；陪玩部署开关与检测名单归后端 |
| 废弃挽留视觉效果 | 独立删除候选 | 当前标记废弃；后续删除连同控件、消费者、测试与文档清理，不在本轮擅自删除 |

桌面最终可收敛到「界面、桌宠与互动、连接、当前角色」；活动阅读与棋盘外观放“界面”下的小节。本机访问授权可在连接区域按需出现，不再有后端“能力与权限”设置页签。

## 7. “一起做事”偏好合并

当前 `ActivitySettingsPage.tsx` 有共享的日/夜主题入口，以及五个本地键：

- `activity.reading.fontSize`、`activity.reading.maxWidth` → 主聊天偏好 / 界面 / 阅读。
- `activity.board.theme`、`activity.chess.pieceStyle` → 主聊天偏好 / 界面 / 棋盘。
- `activity.debug` → 主聊天偏好 / 本机诊断（折叠）。

主题只留一个编辑位置。活动窗口的偏好按钮改为打开主聊天偏好并定位相应小节，不再渲染独立 `ActivityPreferencesPanel`。如果主窗口隐藏，应先显示并聚焦它；返回不结束当前活动。

保留五个存储键，阅读、五子棋、国际象棋已有相应读取与变化订阅。合并仍需真实多窗口验收：旧值保留、立即更新、不重建活动会话、不丢阅读位置。不能只检查偏好窗口自身刷新。

## 8. 观测旧页 → 新归属

| 当前页面或内容 | 新入口及处理 |
|---|---|
| observe-tools、角色权限只读解析、浏览器任务、MCP 调用记录、Agent Runtime 任务/工作区/进程/工作会话接口 | 观测 → 工具与任务：可用性 / 执行记录 / 长期任务。后几项存在接口不等于已有完整 UI，需补页面承接 |
| observe-prompt、observe-dream-prompt、observe-chatlog | 观测 → 对话与生成：按现实/梦境筛选；写开关移出 |
| 模型思考存档、LLM 请求快照 | 运维 → 生成调试；从对应对话记录带权限跳转。思考存档目前有 API，展示仍待建 |
| observe-autonomy、触发器目录、调度器运行部分、群聊仲裁、通道交付状态 | 观测 → 主动行为与通道；调度配置移至功能，手动触发移运维 |
| observe-existence、mood、hidden、growth、memory、memory-events、memory-summary、provenance、vector | 观测 → 记忆与角色状态：默认摘要，记忆证据、溯源和索引下钻；保留真实不同数据源 |
| observe-dream、observe-dream-operations | 梦境会话状态归对话与生成；回流与记忆结果链接到记忆主题；场景执行记录保留可查 |
| observe-visual | 工具与任务中的感知记录；识别调用和费用链接调用与资源 |
| observe-spend、API 调用总账 | 观测 → 调用与资源，分别显示支出意向与实际调用记录，不混算费用 |
| status、resource-completeness | 概览显示健康摘要；配置是否齐全回服务配置；详细阻断归运行总览 |
| system-diagnosis、api-contract、runtime、runtime-signals、logs | 运维 → 诊断与日志；观测首页只展示异常摘要与跳转 |
| owner-turn-api、auth-tokens、users、user-data、冻结 integrations | 运维 → 接口部署 / 访问凭据 / 数据管理；创作素材编辑回创作，冻结项明确只读状态 |

观测优先回答三个问题：现在能不能用、刚才发生了什么、为什么失败。工具详情就近展示可用性和最近失败，完整历史归统一观测。不要另设“启用观测”“配置观测”“能力观测”三个平级页面。

过滤尽量统一为角色、时间、功能、结果。按现有 `turn_id/request_id/task_id/call_id/audit_id` 提供真实可关联跳转；缺少关联键时明确不能关联，不用相近时间拼出虚假的全链路。摘要失败显示“读取失败/状态未知”，不能显示成关闭或无记录。

减少的是导航和重复渲染，不是台账与只读 API。高敏感 Prompt、思考和请求快照不因聚合而扩大到普通客户端权限。

## 9. 中文与统一 UI

统一使用：模型连接、模型方案、角色绑定、多步工具调用、允许使用的工具、执行确认、当前可用、暂不可用、未配置、未测试、需要重启、跟随全局。

API、OCR、TTS、MCP 等常用缩写可跟在中文名称后；地址、模型 ID、协议值、工具 ID 只在填写或诊断详情中保留原文。不要把用户命名的模型方案或远端工具名机械翻译。

统一行组件和状态展示方式；中文值整句翻译，不对英文结果做字符替换。第一层只显示名称、状态、原因和入口，字段名、配置来源路径、执行路径标识折叠到详情。

## 10. 建议施工顺序与验收

1. **状态与归属清单**：确认每项编辑入口、实际消费者、角色覆盖、权限和停用语义；修正多步循环状态偏差及文档漂移。
2. **后端承接**：建立新导航、功能总页、配置摘要与详情；补齐从桌面迁来的思考/对话等完整控件，先保证可读可写和生效反馈。
3. **桌面减法**：移除后端策略编辑，拆角色资产组件，合并活动偏好；保留本机参数、现场操作与授权。
4. **观测整合**：按主题承接旧内容与深链接，移动写控件和调试控制台；验证原记录仍可查。
5. **删除与文档收尾**：移除重复组件、导航、无调用入口和相应僵尸测试；清理过期的控制面审计说明。每单验证后独立提交。

关键验收场景：全局与角色覆盖冲突、开关已开但缺模型/连接、保存失败和需重启、旧配置不丢、普通工具与多步路径分别回归、活动多窗口同步、当前角色切换后的状态刷新、桌面/手机语音与上传不受影响。

管理面静态改动必须更新资源版本、硬刷新并逐页核对可见控件；桌面必须验证真实 Tauri 多窗口。相关接口变更同步三仓总账、设置审计及最小回归测试，未完成部分明确记录 open/roadmap/observe。

本轮只交付审计报告，不调整默认值、运行配置、权限或接口，不将方案记成已完成的产品功能。
