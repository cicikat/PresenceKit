# 测试与合并约束

本规则适用于 PresenceKit 后端仓库所有代码、测试、评估和工作流。修改前确认受影响的实际入口、外部边界和已有覆盖，交付时在工单或 PR 留下对应证据。

## 写测试和修失败

- 为每项修改写清可观测行为和它要防止的故障。通过产品入口触发，断言响应、实际写入、投递、权限拒绝或应当保持为空的副作用。API 验证挂载的路由和实际请求；UI 验证可点击控件、可见结果和实际发出的请求；Prompt 验证生成内容和泄漏边界。
- 复用已有用例和 fixture。只有现有断言漏掉独立回归时才补测。删除重复用例前指出保留的等价覆盖。源码匹配仅用于明确的静态契约，例如禁止直接绕过路径接口或检查缓存版本是否一致。业务测试禁止固定实现字符串、内部调用序列、重复数量、恒真断言和仅能证明替身自身行为的断言。
- 先复现失败并找共同根因。产品行为错误修产品，测试前置条件错误修测试。用显式配置和连接状态激活合法目标，让安全、授权、角色和通道判断实际执行。替身保持调用签名与语义一致；只在测试边界替换网络、设备、时钟等依赖。
- 使用公开测试资产、函数级可写沙盒和合成凭据。共享 fixture 只缓存不可变数据。异步用例管理自身事件循环，结束时等待任务退出，恢复配置、注册表和缓存。时间与并发用受控时钟、事件、屏障或有界等待验证。重启契约用独立进程和实际持久化目录验证。
- 关键权限、脱敏、投递和幂等回归在改动时先证明会失败，再验证修复。复用对应的故障注入或短暂撤销目标修复，记录失败的业务断言。用例收集、fixture 或环境失败不算捕获了回归。
- 禁止通过删测、放宽业务断言、吞异常、新增跳过或预期失败让红灯消失。平台、可选扩展和跨仓依赖确实无法满足时，按实际条件标记、给出原因和独立验证入口。CI 显示分类，拒绝未预期 skip 和 XPASS。

## 选择验证并记录证据

| 验证层 | 应执行的验证 |
|---|---|
| 定向 | 先跑改动对应的用例，修失败时重跑同组失败项，必要时串行复查共享状态。 |
| Smoke / Regression | 用 `pytest -m smoke` 运行核心验收，核心清单维护在 `tests/ci_suites.py`。全量按 AGENTS.md 并行运行，PR 验证 Python 3.10 和 3.12。 |
| Browser / Contract | 改 Admin 行为时按缓存规则更新资源并执行浏览器验收。改跨仓协议时跑三仓合同，记录各自完整 SHA 和实际结果。单端 mock 和静态检查只作为各自覆盖范围内的证据。 |
| Offline eval | 离线门禁检查最低用例数，错误通过非零退出码传出。管道启用 `pipefail` 并在失败时上传日志。可选在线报告标注 `report_only`，计费或真实服务验收须已有授权。 |

PR 说明写明所防回归、实际执行命令或运行链接、Python/平台、通过/失败/跳过情况。浏览器、设备和外部服务没有执行时标注未验证。跨仓证据只适用于记录的三仓 SHA，其他组合标注 `not_verified`。

## Push 后直接完成合并

1. 用户已授权 push 和合并时，在独立分支提交并 push，创建或更新指向 `main` 的 PR。同批工单按 AGENTS.md 保留独立提交。
2. 跟进 PR 当前 head 的 Smoke、双版本全量、浏览器和离线评估。按影响范围确认跨仓或设备验收。失败时定位原因、修复、重新推送并核对新 head 的检查；上一提交、旧 base 或被取消的结果均不能用于准入。
3. 检查通过、当前 PR 可合并时直接执行合并，无需再次询问或把合并留给用户。CLI 合并绑定已核对的 head，例如 `gh pr merge <PR> --merge --match-head-commit <SHA>`。合并后核对 PR 为 `MERGED`、远端 `main` 包含合并提交，并跟进本次合并触发的必跑检查。
