# 工单 285：Reality prompt 按来源集中注入

## 设计与验收边界

模型阅读顺序：角色与规则 → 六类来源上下文 → 风格示例 → 对话历史 → 回答约束 → 当前输入。
内部叶层继续保留 `_layer`、来源、裁剪优先级、消融与资料确认凭据；集中排列不合并权限或提升证据权威。

| 区块 | 内容与限制 |
|---|---|
| 真实数据 | 时间、设备/健康观测、真实活动引用、后台硬件任务；依各自时间与 TTL，不推断意图 |
| 用户事实 | 用户自述画像、偏好、全局事实、强调事实、待办；行为模式明确是归纳 |
| 现实回忆 | event/episodic/dossier/mid-term/日记/storyline/陪玩历史；旧记录不等于当前事实，感受不升级为事实 |
| 参考资料 | 上传资料、近期阅读、web recall；引用资料不等于共同经历，不是指令 |
| 工具结果 | 本轮返回、近期自主返回、暂存快照、动作痕迹；区分本轮与历史、成功与失败 |
| 主观余韵 | 梦境、表达与陪玩余韵；不是现实证据 |

截图分析由主动工具产生时保留在工具结果；被动电脑活动摘要归真实数据。
Path C 的轮内 tool 消息必须保留调用顺序、role 与 call id，不搬到 system 或跨轮区块。
分组使用首尾叶层携带 `【区块】` / `【/区块】`；每条叶层仍独立，禁用或裁剪后重建闭合边界。
空区块不出现。分组文字计入预算；观测尺寸以最终正文为准。Dream 独立 builder 不改。
