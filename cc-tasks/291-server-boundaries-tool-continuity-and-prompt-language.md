## 已核对的事实

1. `core/perception/screen_observation.py` 请求客户端 poll/result 上传新帧，不在后端截屏；`core/tools/screen_peek.py` 读取 sensor 上传的实时文字快照。
2. `core/coplay/observer.py` 使用 mss 截后端屏幕；`core/coplay/watcher.py` 读后端 Steam 注册表、进程和库路径并拉起本地桌宠。单独设置 remote_server 并未迁移这些采集器。
3. `core/deployment_capabilities.py` 已屏蔽部分关机、文件工作区与进程工具，桌面动作已有客户端路径；需沿调用链核对，不重建第二套部署开关。
4. 主动结果保存上限12条/24小时，投影最近3条，每条存储摘要至多2000字符，展示再截至1400；并非三个完整原始返回。主动循环与普通聊天均调用 context_continuity。
5. `pin_tool_result` 已存在：最多3项、每项2000字符、1..10个成功用户轮、硬过期最多24小时；自主 tick 不扣轮。权限、工具关闭、敏感结果排除仍有效。
6. dispatcher 在摘要末尾附 result_id；主动循环再次截断至1400字符，长摘要会丢失末尾 ID。普通 Path C 的2000字符包装也需另行核对。

## 服务器迁移分工

| 能力 | 当前证据与迁移归属 |
|---|---|
| NapCat/QQ | 登录进程与后端可同服务器部署；需按目标系统核对现有运行配置和登录数据目录，实际扫码、重启恢复及收发尚未执行 |
| 微信 | 已有独立 Node bridge 与 Dockerfile；登录数据挂载 /state，桥接密钥由环境注入。应随服务器迁移并持久化，不能只复制后端配置 |
| 小红书 | reader 独立服务持有 cookies.json；remote_server 下后端不托管本机 reader 进程，应部署服务器侧独立服务并配置 reader_url 和持久卷 |
| 按需屏幕/peek | 已从用户设备获取截图/文字；保留客户端采集。需真实远程验收授权、活跃设备、超时、撤权与重连 |
| 陪玩 | 后端直接截屏、读 Steam/进程、spawn 桌宠。客户端采集迁移为 open，整链尚未改造 |
| 桌面动作 | 已有 WebSocket 客户端动作与 ack 路径；离线不能回退操作服务器，需按实际动作验收 |
| workspace/process/关机睡眠 | 已有 remote_server 禁用策略；若需操作用户电脑，要另接客户端执行协议，不能直接解除后端闸门 |
| 摄像头/本地模型/TTS | 区分客户端帧采集与后端模型调用；摄像头模型路由当前要求后端 loopback。原电脑的 localhost 配置不能直接沿用到服务器，需要服务器部署模型或明确的新路由设计 |
| HDS/ESP32/其他硬件 | 网络设备需要重配可达的接入地址；电脑本地蓝牙/Intiface 进程不会随后端迁移。当前未做真实设备验证 |
