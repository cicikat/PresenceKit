# 258 — 角色主题档案、实时接续与静默记忆整理

日期：2026-09-19。状态：规划完成，A–G 全部未施工。本文件是拟议合同，不代表 current。

本次仅编制工单，不启用调度、不运行模型、不迁移或删除生产记忆。旧数据整理见 [259](259-memory-history-reconciliation.md)。

## 目标与主体

让同一角色维护有证据支撑的主题理解：自主命名、分类、关联、修订；聊天按需读写，夜间由同一角色的专门副链增量整理。后台不走主聊天队列，不制造 assistant turn，不向用户发送整理通知。主链和副链调用同一个记忆 capability，不能各维护一套事实或权限。

角色决定语义：哪些经历相关、叫什么名字、哪些理解需要修正、哪些内容值得长期保存。程序负责来源、去重、版本、权限、计数、提交和恢复，不预设“奶茶”等业务分类。未分类、暂不归纳是合法结果。允许保留角色感受，但不得将感受升级成用户事实。

产品目标：实施并验收上线后，当晚静默启动；翌晨当前话题与约定首夜范围的记忆可以连贯召回，并可核对剩余历史积压。首夜范围与全历史完成分别验收，禁止预先承诺未知数据量一夜处理完。当前仅写工单，不意味着今晚已有后台任务。

## 拟议数据合同

沿用按 owner + char + realm 隔离的证据库；主题使用统一派生存储，不按名字创建独立物理数据库。新增路径经 sandbox / data registry。数据库落点在 A 确定，原则是派生状态可重建、原始证据不复制、不引入新的证据权威。

| 对象 | 必须表达 |
|---|---|
| dossier | 稳定 ID、角色自定标题/别名、主题说明、active/dormant/merged/retired、revision、合并重定向 |
| occurrence | 一次现实经历的稳定 ID、参与者、发生时间/不确定区间、明确/观察/推测来源、证据引用；同一次经历多次提及不重复计数 |
| membership / relation | 多主题归属；同主题与时间后续分别表达；模型推测因果保持 tentative，不写成系统确定性边 |
| understanding | 当前有效概括、条件、时间范围、支持与反例、置信理由、角色感受标识、证据覆盖截止点、revision、supersedes |
| revision / operation | 旧值引用、修改理由、来源、执行主体与链路、预期 revision、幂等键、提交结果、恢复关联 |
| processing state | 复用 259 的源清单/处理状态与变更队列，新增和历史走同一协议；不将 Task receipt 当正文或进度权威 |

计数由确认且去重的 occurrence 计算，标明时间窗、已知覆盖及未知字段；“记录中至少 N 次”不等于“生涯总共 N 次”。计划、取消、转述、假设和助手建议不计为已发生的用户行为。重复摘要不能成为独立支持证据。稀疏样本不作稳定画像；季节/情绪相关归纳保留反例，禁止将相关性标成因果。

当前理解可显式替换，历史修订可查；原证据保持既有更正/墓碑语义。角色可自主撤回自己的错误概括、移除分类关联或将派生条目退出召回，不逐次要求用户确认；这些动作可逆。用户遗忘、证据撤回应使所有相关派生结论立即失效或待重算，包含索引、缓存和旧召回路径。物理销毁另走现有保留/遗忘政策。
