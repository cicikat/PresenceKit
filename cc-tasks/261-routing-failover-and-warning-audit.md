## 依据与结论

用户提供的 00:10–12:10 审计报告指出 sensor 裁决、consolidation、爱意识别等失败。报告的 API 失败条数、error.log 异常头和业务事件不是同一统计口径，不能直接相加或据此推导独立业务失败率；本单不重新核验其 26/115 计数。

源码已确认：

- `core/model_registry.py::_resolve_preset_name` 是缺配置时的路由选择，不是请求失败后的跨 preset 兜底。普通用途（含 monologue）实际顺序为用途映射 → default_preset → chat → 首个 preset，部分文档简写“回落 chat”不完整。
- `core/scheduler/sensor_judge.py::judge` 直接调用协议出口，10 秒墙钟限制、零 SDK retry，已有按 preset/category 区分的熔断和半开恢复；只改 `llm_client.chat` 会漏掉该入口。
- registry 为普通 OpenAI SDK client 默认设置 2 次 retry；原生 Anthropic 为独立 HTTP 路径，不能统一声称所有用途都有相同重试。`error_handler.with_retry` 的存在不表示所有调用都使用了它。施工 A 必须盘点接入入口及外层重试，避免重试相乘。
- `core/thinking.py` 通过 `call_category="monologue"` 额外生成正文，清理思考标签后注入当前回复上下文，并单独归档。它是角色独白草稿，不等于主模型原生 reasoning；可用同一或不同 preset。失败会跳过独白继续主回复，但额外请求仍增加发送前延迟。
- `admin/static/js/settings.js::MR_CATEGORIES` 已包含 monologue，模型路由 fragment 和中英文说明也存在。本单完善可发现性和 effective state，不再新增重复 category。用户所见入口缺失或错误原因尚未复现。
- `main.py` 的 root logger 目前只有 StreamHandler；`core/error_handler.py` 单独写 error.log traceback。新增 WARNING 持久化须保留这条旧链。

## 拟定行为合同

每个 Routing Profile 的用途行显示“主 Preset / 兜底 Preset（可不选）”。旧配置默认关闭失败兜底，不自动替用户选择模型。兜底选择同样跟随实际生效的角色绑定 profile，不从无关全局 profile 借用。现有 category → preset 字符串结构保留，新增独立的按 profile/category 索引的 `fallback_routes` 映射（最终 schema 在 A 中固定），避免把嵌套配置误当 category。

主路由结束其现有适用重试后，若最终属于允许兜底的失败，最多切换一次；兜底请求零 SDK retry，不递归兜底。主路由熔断打开时可直接尝试已配置的兜底，独立维护各 preset 健康状态。未配置、预算不足或兜底失败时，保留该业务原有失败行为。

默认允许连接错误、超时、429、上游 5xx，以及明确识别的上游地域拒绝；不能把所有 403 都当 geo_blocked。普通鉴权错误、错误请求参数、本地程序异常、取消、权限拒绝与内容安全拒绝不自动切换。业务明确要求正文或 schema 时，空响应、截断或格式不合法由对应验证器判定；合法工具调用或合法 drop/false/无新记忆结果不是失败。禁止通过更换模型绕过安全拒绝。

兜底必须沿目标 preset 重新适配协议、prompt style、生成参数及工具能力，从未被改写的语义输入构建请求。显式指定 preset 的任务绑定默认不自动改用 profile 兜底；不兼容的兜底配置应提示并拒绝生效。

总墙钟预算必须包含 SDK retry、等待和兜底，不能把单次 HTTP timeout 当总上限。sensor/monologue 首版建议主 10 秒 + 兜底最多 10 秒，总上限 20 秒；主熔断打开时不消耗主尝试预算。consolidation 等普通用途先盘点既有外层预算，再在 A 中逐项写明总上限，不擅自叠加无限等待。取消、任务到期和服务关闭优先于兜底。

## D — P1：聊天尾部控制标记泄露闭环

已确认的修复历史与遗漏：2026-09-19 的 `c5ec8e3`（`fix: strip false tail marker from replies`）将工具循环自然结束时的 `turn.content` 改为 `display_text`，该修复仍在。`core/pipeline.py::run_agentic_loop` 用过工具后、步数/总预算耗尽后以及空完成后的收尾，仍通过 `run_llm` / `run_llm_stream` 再生成正文，没有经过同一尾部标记清理；上下文仍保留允许输出 `{false}` 的 relay 指令。`strip_render_tags` 只处理 XML 类标签，不会拦住该标记。自然结束后的反坍缩重试也可能生成新文本，需纳入出口核对。
